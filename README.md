# 找回消失的垃圾桶

市政 debug松 題目 #2。用人流、店家與市民通報，算出台北哪裡最缺垃圾桶、該用哪種方式處理，並公開增設進度。

台北行人專用垃圾桶從全盛時期近 3,000 組，縮減到約 800 組。這個網站回答三個問題：哪裡最缺？為什麼？市府做到哪裡了？

## 功能

| 分頁 | 做什麼 |
| --- | --- |
| 增設建議 | 六角網格依「缺口」上色。6 個權重滑桿可以即時重算；點一格看排名與原因拆解；列出建議增設前 30 名 |
| 填滿模擬 | 假設每個桶都有感測器，模擬一週的填滿過程，比較「固定排程」與「感測派車」的滿溢時數和出車次數，列出派車建議 |
| 市民通報 | 點地圖通報亂丟垃圾、清潔箱滿溢、家戶垃圾棄置；每格依通報量給出「增設／加強清運／加強取締」建議 |
| 施政進度 | 30 個建議點的設置狀態、更新日期與負責清潔隊，可依行政區篩選 |

## 資料來源：真實 vs 模擬

目前**全部使用模擬資料**。程式在 `data/raw/` 放入真實檔案後會自動改用真實資料，網頁上每個圖層與數字旁都會標示「真實」或「模擬」。檔名與欄位見 [`data/NOTES.md`](data/NOTES.md)。

| 資料 | 現況 | 說明 |
| --- | --- | --- |
| 行人專用清潔箱 | 模擬 | 真實來源：[環保局開放資料](https://data.gov.tw/dataset/121355)。模擬 800 組，刻意在部分捷運站與夜市周邊留下缺口 |
| 捷運站與人流 | 模擬 | 真實來源：[捷運各站分時進出量](https://data.taipei/dataset/detail?id=63f31c7e-7fc3-418b-bd82-b95158755b4d)。目前站點座標為近似值，人流為模擬 |
| 公車站牌 | 模擬 | 真實來源：[公車站牌位置](https://data.taipei/dataset/detail?id=48aa5bca-2a4f-4fb7-a658-43cba51d5d56) |
| YouBike 站點 | 模擬 | 捷運站與部分公車站旁撒點 |
| 飲料店、小吃店 | 模擬 | 依捷運人流與 6 個夜市位置撒點 |
| 歷史市民通報 | 模擬 | 店家多、附近沒有桶的地方較常出現 |
| 智慧垃圾桶填滿紀錄 | 模擬 | 主辦說明此資料不存在 |
| 增設進度 | 模擬 | 從建議前 30 名隨機指定狀態 |

所有模擬都固定 `seed=42`，每次產生的結果相同。網頁上使用者新增的通報只存在該瀏覽器的 localStorage，不收集任何個資。

## 演算法

把研究範圍（各捷運站外約 1.5 公里）切成 H3 六角網格（解析度 9，每格約 0.1 km²，共 1,637 格）。

**需求**＝Σ 權重 × 標準化特徵，6 個特徵：

| 特徵 | 計算方式 | 預設權重 |
| --- | --- | --- |
| 捷運人流 | 500 m 內各站每日進出人次，依距離線性衰減 | 0.30 |
| 公車站 | 本格＋相鄰 6 格的站數 | 0.20 |
| YouBike | 同上 | 0.10 |
| 飲料店、小吃店 | 同上 | 0.20 |
| 市民通報 | 本格通報數（含使用者新增） | 0.15 |
| 現有桶填滿速度 | 本格＋相鄰格的桶平均每小時填滿比例 | 0.05 |

標準化：0 維持 0，正值換成在所有正值中的百分位數，避免大量空格子拿到中間分數。

**供給**＝本格清潔箱數＋0.5 × 相鄰格清潔箱數。**缺口**＝需求 ÷ (1＋供給)。

**建議增設點**：依缺口由高到低挑選，需求須達總權重的 35%，且彼此不相鄰，取前 30 名。公車站權重較高，依據是環保局過去的清潔箱設置作業程序：優先設在公車站牌多的地點。

**市民通報的處置建議**（同一格內）：通報 3 件以上時，沒有桶 → 增設；有桶且每桶一週滿溢 10 小時以上 → 提高清運頻率或改用智慧桶；有桶但不常滿 → 加強巡邏與取締。

**填滿模擬**：每小時增加量＝桶的填滿速度 × 時段係數（捷運分時曲線）× 週末係數＋雜訊。A 固定排程每天 06:00、14:00、22:00 清空；B 感測派車填到 80% 就派車、下一小時清空。模擬結果：滿溢 14,918 → 1,058 桶時，出車 16,800 → 12,623 次。

## 如果市府上任 100 天內要落地

| 期間 | 主責局處 | 做什麼 |
| --- | --- | --- |
| 第 1–30 天 | 環保局、資訊局 | 開放清潔箱裁撤紀錄與違規棄置資料，換成真實資料，確定權重 |
| 第 31–60 天 | 環保局、區清潔隊 | 選 2 個行政區試點：建議前 30 點會勘、增設；50 個桶裝填滿感測器 |
| 第 61–100 天 | 研考會（1999） | 通報整合進陳情系統，由環保局每週更新施政進度頁 |

成本粗估（新聞報導數字）：北市一組行人清潔箱設置成本約 1.2 萬元，增設 30 組約 36 萬元；桃園智慧垃圾桶感應模組年租金約 4 萬元，50 組約每年 200 萬元。

## 專案結構

```text
pipeline/        Python：把原始資料算成靜態 JSON（只需要跑一次）
  01_load.py       讀 data/raw/ 的真實資料
  02_simulate.py   補齊模擬資料
  03_grid.py       H3 網格特徵 → grid.json 等
  04_fill_sim.py   填滿模擬 → fill.json
  05_progress.py   施政進度 → progress.json
web/             Vite + React + TypeScript + Leaflet：讀 JSON、畫地圖
  src/lib/score.ts 需求、缺口、建議點（和 pipeline/common.py 規則相同）
  src/tabs/        四個分頁
data/raw/        原始下載檔（不進 git）
```

## 開發

```bash
# 產生資料（需要 Python 3.11+）
pip install -r pipeline/requirements.txt
make all

# 網站（需要 Node 22）
cd web
npm install
npm run dev

# 測試
make test
```

## 部署

push 到 `main` 後，GitHub Actions 會跑測試、build，並部署到 GitHub Pages（`.github/workflows/deploy.yml`）。第一次使用前，到 repo 的 Settings → Pages，把 Source 設成「GitHub Actions」。
